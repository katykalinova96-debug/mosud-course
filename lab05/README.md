**Вариант:** 6  
**Множество штатов S:** PA, AM, RO

## Цель работы

Формализовать условие «для всех», реализовать реляционное деление тремя способами в PostgreSQL и проверить эквивалентность полученных множеств.

## Исходные данные и условие

Используются таблицы `olist.customers`, `olist.orders`, `olist.order_items`, `olist.products`, а в дополнительном задании — идентификаторы продавцов из `olist.order_items`. Учитываются только заказы со статусом `delivered`; товары с `product_category_name IS NULL` исключаются.

Требуется найти категории, присутствующие в доставленных заказах покупателей **каждого** из штатов PA, AM и RO.

## Проверка исходных данных

| Штат | Товарных позиций | Уникальных категорий |
|---|---:|---:|
| AM | 163 | 38 |
| PA | 1 054 | 52 |
| RO | 273 | 42 |

## Реализации реляционного деления

1. **Двойной `NOT EXISTS`**: не существует обязательного штата, для которого отсутствует продажа категории.
2. **`GROUP BY` и `HAVING COUNT(DISTINCT customer_state)`**: число разных обязательных штатов, в которых встречалась категория, равно числу штатов в `target_states`.
3. **`EXCEPT` совместно с `NOT EXISTS`**: множество обязательных штатов за вычетом штатов продажи категории должно быть пустым.

## Результаты выполнения

| Показатель | Результат |
|---|---:|
| Категории — двойной `NOT EXISTS` | 29 |
| Категории — `GROUP BY/HAVING` | 29 |
| Категории — `EXCEPT/NOT EXISTS` | 29 |
| Различающиеся категории, каждое из 6 сравнений `EXCEPT` | 0 |
| Число категорий-кандидатов | 74 |
| Число обязательных штатов в эксперименте с пустым S | 0 |
| Категорий, удовлетворяющих условию для пустого S | 74 |
| Продавцов, продававших покупателям каждого из трёх штатов | 26 |

Все шесть попарных проверок разности множеств (`EXCEPT` в обоих направлениях для каждой пары методов) вернули ноль. Следовательно, три способа дали одинаковый набор из **29 категорий**.

## Диагностическая таблица

Для первой найденной категории (в выводе PostgreSQL значение названия показано пустым):

| Штат | Число различных доставленных заказов |
|---|---:|

Пустое отображение названия не означает `NULL`: по условию запроса строки с `NULL` исключены. Для более наглядной диагностики можно выбрать следующую категорию с непустым названием, не меняя основного результата.

## Эксперимент с пустым множеством штатов

При пустом `target_states` подходящими оказались все **74 категории-кандидата**. Универсальное утверждение «категория встречается в каждом штате пустого множества» истинно, поскольку не существует штата, для которого оно нарушается. При реализации через `GROUP BY/HAVING` пустое множество требует отдельной обработки: фильтрация продаж по пустому множеству сама по себе не сформирует группы категорий.

## Вывод

В работе найдены 29 категорий, встречавшихся в доставленных заказах покупателей всех трёх штатов PA, AM и RO. Двойной `NOT EXISTS`, `GROUP BY/HAVING` и `EXCEPT/NOT EXISTS` дали эквивалентные результаты, что подтверждено шестью проверками `EXCEPT`. Предварительная подготовка временных данных уменьшила повторные вычисления и позволила выполнить запросы. Проверка с пустым делителем продемонстрировала вакуумную истинность универсального условия. Дополнительно найдены 26 продавцов, связанных с покупателями каждого из трёх штатов.
