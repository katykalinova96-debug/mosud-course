Используются `olist.customers`, `olist.orders`, `olist.order_items`. Учитываются только заказы `delivered`. Множества содержат уникальные `product_id`.

## Результаты

| Показатель | Количество |
|---|---:|
| Все позиции заказов из ES до DISTINCT | 2 225 |
| A = уникальные товары ES | 1 648 |
| Все позиции заказов из RJ до DISTINCT | 14 143 |
| B = уникальные товары RJ | 7 672 |
| A ∪ B (`UNION`) | **8575** |
| A ∪ B (`UNION ALL`, количество строк) | 9 320 |
| A ∩ B (`INTERSECT`) | **745** |
| A − B (`EXCEPT`) | **903** |
| B − A (`EXCEPT`) | **6927** |

## Выводы

`UNION` устраняет совпадающие `product_id`, `UNION ALL` сохраняет их, поэтому результат `UNION ALL` содержит 9 320 строк, в том числе повторяющиеся товары из двух множеств. `INTERSECT` оставляет товары, купленные в обоих штатах. `EXCEPT` показывает товары только одного штата относительно другого.

Объединение и пересечение коммутативны: `A UNION B = B UNION A` и `A INTERSECT B = B INTERSECT A`. Разность некоммутативна: `A EXCEPT B` в общем случае не равно `B EXCEPT A`. Пересечение через `EXISTS` содержит 745 уникальных товаров, что совпадает с результатом `INTERSECT`.

`DISTINCT`, `UNION`, `INTERSECT`, `EXCEPT` возвращают уникальные строки (множества), а `UNION ALL` и `SELECT` без `DISTINCT` могут содержать повторения (мультимножества). Порядок строк без `ORDER BY` не гарантируется.
