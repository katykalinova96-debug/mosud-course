## Цель работы

Освоить соединения нескольких связанных таблиц PostgreSQL и научиться предотвращать ошибочное размножение строк при соединениях. На данных Olist выявить повторных покупателей и сравнить даты их первой и последней покупки.

## Использованные таблицы и связи

Основной анализ построен на таблицах `olist.customers`, `olist.orders`, `olist.order_items`.

- `customers → orders`: одна запись `customers` соответствует одному заказу (`orders.customer_id`), но один реальный покупатель, обозначенный `customer_unique_id`, может иметь несколько записей в `customers` и несколько заказов. Следовательно, по `customer_unique_id` связь с заказами имеет характер **1:N**.
- `orders → order_items`: **1:N**, так как заказ может включать несколько позиций. При обычном `JOIN` один заказ повторяется столько раз, сколько у него позиций.
- `orders → order_payments`: **1:N**, поскольку заказ может иметь несколько записей об оплате.
- `orders → order_reviews`: потенциально **1:N** (для одного заказа может быть несколько отзывов).

При вычислении числа заказов важно не принимать число строк после соединения с позициями заказа за число отдельных заказов.

## 1. Повторные покупатели

| Показатель | Результат |
|---|---:|
| Уникальных покупателей, совершивших заказы | 96 096 |
| Покупателей с двумя и более заказами | 2 997 |
| Максимальное число заказов у одного покупателя | 17 |

Для повторных покупателей определены число заказов, дата первой покупки (`MIN(order_purchase_timestamp)`), дата последней покупки (`MAX(order_purchase_timestamp)`), промежуток между ними и число товарных позиций.

Например, покупатель с `customer_unique_id = 8d50f5eadf50201ccdcedfb9e2ac8455` совершил **17 заказов**; первая покупка — **2017-05-15 23:30:03**, последняя — **2018-08-20 19:14:26**, промежуток — **461 день 19:44:23**. Для него основной запрос показал **16 товарных позиций**. Число позиций не обязано совпадать с числом заказов.

## 2. LEFT JOIN и антисоединение

| Показатель | Результат |
|---|---:|
| Всего заказов | 99 441 |
| Заказов без позиций в `order_items` | 775 |
| Заказов без связанных отзывов в `order_reviews` | 768 |

`LEFT JOIN` позволяет сохранить заказы, для которых отсутствуют связанные строки. Антисоединение позволяет отобрать именно такие заказы — например, через `LEFT JOIN ... WHERE review_id IS NULL` или `NOT EXISTS`. Количество заказов без позиций и без отзывов относится к разным связям, поэтому эти значения не обязаны совпадать.

## 3. Ошибочное соединение и исправление

В эксперименте прямой `JOIN` таблиц `order_items` и `order_payments` по `order_id` размножает платежи у заказов с несколькими товарными позициями. В результате сумма платежей завышается.

| Показатель | Результат |
|---|---:|
| Строк после ошибочного соединения (`joined_rows`) | 117 601 |
| Строк платежей в выбранной совокупности (`payment_rows`) | 103 056 |
| Сумма платежей после ошибочного JOIN | 20 308 134,71 |
| Корректная сумма платежей | 15 846 280,17 |
| Завышение суммы | **4 461 854,54** |

После предварительной агрегации позиций и платежей до одной строки на заказ повторный подсчёт устранён.

| Показатель после исправления | Результат |
|---|---:|
| Заказов с позициями и платежами | 98 665 |
| Количество товарных позиций | 112 647 |
| Количество записей об оплате | 103 056 |
| Общая стоимость товарных позиций | 13 591 508,73 |
| Общая сумма платежей | 15 846 280,17 |
| Совпадение проверочной и фактической суммы (`sums_match`) | `true` |

Стоимость позиций и сумма платежей отражают разные показатели, поэтому сравнивать их как равные суммы не требуется. Проверка `sums_match = true` относится к корректному расчёту суммы платежей.

## 4. Реляционная алгебра

Пусть `C = customers`, `O = orders`, `I = order_items`. Соединение клиентов и заказов можно записать как:

`C ⋈_{C.customer_id = O.customer_id} O`

Добавление позиций заказа:

`(C ⋈_{C.customer_id = O.customer_id} O) ⋈_{O.order_id = I.order_id} I`

Это композиция эквисоединений, после которой для анализа повторных покупателей выполняется группировка по `customer_unique_id` с подсчётом уникальных заказов и вычислением минимальной и максимальной дат покупки. Группировка с агрегатами является расширением классической реляционной алгебры. Если нужно сохранить заказы без позиций, второе внутреннее соединение заменяют левым внешним соединением.

С помощью `LEFT JOIN` обнаружены **775** заказов без товарных позиций, а антисоединением — **768** заказов без отзывов. Предварительная агрегация по `order_id` устраняет размножение строк; правильность суммы подтверждена проверкой `sums_match = true`.
