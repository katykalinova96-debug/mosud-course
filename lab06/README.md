## Задача

Найти заказы, сумма платежей по которым превышает сумму `price + freight_value` по всем товарным позициям соответствующего заказа.

Цель работы — освоить скалярные и коррелированные подзапросы, изучить логику предикатов и сравнить решение на основе подзапросов с альтернативной реализацией через JOIN и CTE.

## Что реализовано

1. **Основное решение.** Коррелированные скалярные подзапросы по `order_id` вычисляют общую сумму платежей и стоимость товарных позиций с доставкой. Оператор `EXISTS` проверяет наличие связанных записей.

2. **Альтернативное решение.** Суммы платежей и товарных позиций предварительно вычисляются с помощью CTE (`WITH`) и `GROUP BY`, после чего полученные результаты соединяются по `order_id` через `JOIN`.

3. **Проверка эквивалентности.** Оператор `EXCEPT` используется в обе стороны для сравнения наборов `order_id`, полученных основным и альтернативным запросами. Отсутствие различий подтверждает совпадение найденных заказов.

4. **Демонстрация ANY.** Отдельный запрос показывает применение оператора `ANY` для сравнения суммы платежей хотя бы с одним значением стоимости товарной позиции. Такая проверка отличается от сравнения с суммарной стоимостью всех позиций заказа.

SQL-скрипт `lab06.sql` выполняется целиком в одном сеансе PostgreSQL, поскольку временные представления `lab06_main` и `lab06_alt` существуют только в рамках текущего сеанса.

## Ответы на контрольные вопросы

**1. Чем коррелированный подзапрос отличается от независимого?**

Коррелированный подзапрос использует значения текущей строки внешнего запроса. В данной работе связь осуществляется через `o.order_id`. Независимый подзапрос не зависит от значений внешнего запроса и может выполняться самостоятельно.

**2. В каких случаях EXISTS логически удобнее IN?**

Оператор `EXISTS` удобен, когда необходимо проверить наличие хотя бы одной подходящей строки. Он возвращает `TRUE`, если строка существует, и `FALSE`, если подходящих строк нет. Оператор `IN` проверяет принадлежность значения набору значений. При использовании `NULL` необходимо учитывать различия между `NOT EXISTS` и `NOT IN`.

**3. Почему скалярный подзапрос должен возвращать не более одной строки?**

Скалярный подзапрос используется там, где ожидается одно значение. Если он возвращает более одной строки, PostgreSQL выдаёт ошибку. Агрегатная функция `SUM` без `GROUP BY` возвращает одно значение, которое может быть `NULL`.

## Пояснение к подсчётам

Сравнение сумм выполняется отдельно для каждого заказа по `order_id`.

Прямое одновременное соединение исходных таблиц `order_payments` и `order_items` может приводить к размножению строк, поскольку одному заказу могут соответствовать несколько платежей и несколько товарных позиций.

Для исключения этой проблемы суммы рассчитываются отдельно по каждому заказу, а затем результаты соединяются. Такой подход обеспечивает корректность итоговых вычислений.
