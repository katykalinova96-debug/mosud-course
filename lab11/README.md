## 1. Представления

`lab.v_order_summary` содержит одну строку на заказ: `order_id`, дату покупки, штат клиента, число товарных позиций и сумму `price + freight_value`. Для позиций используется `LEFT JOIN`, чтобы не потерять заказы без строк в `order_items`.

`lab.mv_monthly_state_sales` хранит агрегаты по месяцу покупки и штату: количество заказов и сумму стоимости товаров с доставкой. Для обновления сохранённых данных используется `REFRESH MATERIALIZED VIEW lab.mv_monthly_state_sales`.

## 2. Аналитический запрос с CTE

Запрос состоит из трёх именованных CTE:

1. `order_data` — формирует месяц покупки, штат и стоимость заказа.
2. `state_monthly` — рассчитывает количество заказов и общую сумму по месяцу и штату.
3. `ranked_states` — ранжирует штаты по сумме внутри каждого месяца с помощью `ROW_NUMBER()`.

В итоговом результате выводятся три штата с наибольшей суммой продаж в каждом месяце.

## 3. Иерархия географических данных

Таблица `lab.geo_tree` построена на основе существующих полей `customer_state` и `customer_city` в `olist.customers`. Включены все представленные штаты и до 20 городов с наибольшим числом клиентов в каждом штате.

```text
BR (страна)
└── ST:SC (штат Santa Catarina)
    ├── CT:SC:<город 1>
    ├── CT:SC:<город 2>
    └── ... (до 20 городов)
```

`node_id` — первичный ключ; `parent_id` — внешний ключ на `node_id` той же таблицы. `node_type` принимает значения `country`, `state` или `city`.

## 4. Рекурсивные запросы

**Прямой обход.** От узла `ST:SC` выводятся все его потомки с полями `depth`, `node_id`, `path`, `node_name`. Глубина корневого узла — 0, глубина городов — 1. Пример формата пути: `ST:SC -> CT:SC:florianopolis`. По результатам запуска поддерево содержит 21 узел: штат и 20 городов.

**Обратный обход.** Выбирается первый по `node_id` город штата SC — `balneario camboriu` — и выводятся его предки до `BR`. Полученная цепочка: `CT:SC:balneario camboriu -> ST:SC -> BR`. Глубины узлов — 0, 1 и 2.

**Количество потомков.** От каждого узла типа `state` выполняется обход вниз; сам штат не учитывается при подсчёте. При трёхуровневой иерархии потомки штата — его города.

**Защита от циклов.** В обоих обходах используется массив `visited`; перед посещением очередного узла проверяется, что его ID отсутствует в массиве. В дополнительном задании цикл создаётся только во временной копии таблицы, основная `lab.geo_tree` не изменяется.

Рекурсивный CTE содержит две части: базовая выбирает стартовый узел, рекурсивная присоединяет дочерние или родительские узлы. Выполнение завершается, когда на следующей итерации не находятся новые строки. Проверка `visited` дополнительно предотвращает бесконечный обход циклов.

## 6. Контрольные вопросы

**1. Чем VIEW отличается от MATERIALIZED VIEW?**  
Обычное `VIEW` хранит определение запроса и получает результат при обращении. `MATERIALIZED VIEW` сохраняет результат физически; после изменения исходных данных его необходимо обновлять через `REFRESH`.

**2. Что является условием завершения рекурсивного CTE?**  
Рекурсия заканчивается, когда очередное применение рекурсивной части не добавляет новых строк. Для иерархии также важно исключать повторные посещения узлов, если есть циклы.

**3. Как рекурсивный запрос связан с транзитивным замыканием отношения?**  
Связь «родитель — ребёнок» задаёт непосредственные переходы. Рекурсивный запрос последовательно применяет их и получает все достижимые узлы, то есть транзитивное замыкание этой связи от выбранного узла.
